# ToolHorizon

在**单张 24GB 消费级显卡**上研究长链路多工具 Agent 的 RL 训练稳定性 ——
以及一个此前没被当作观测对象的东西：**工具使用行为本身的退化**。

> 降级复现 `agentic-grpo-longhorizon`（2×A800 / 7B policy / 72B 用户模拟器）的结论，
> 并补上它没有看的第四维。本项目用约 **1/10 算力**：
> **1× RTX 4090D 24GB + Qwen2.5-1.5B-Instruct + LoRA r=16**。

---

## 一句话结论

> **在这个尺度上，瓶颈不是"模型学坏了"，而是"根本没有信号"。**

组内零方差率（多少比例的 prompt 组**不产生任何梯度**）在四种算法配置下
**全部停在 87–93%** —— 换损失函数、换采样策略都压不下去。
但同一批实验里，工具调用次数从 gold 的 **2.1 倍一路掉到 0.49 倍**，
**穿过了正常区、落到另一个极端**。

## 1. 研究问题

长链路工具 Agent 的 RL 训练会"坍塌"（reward 先升后降）。参考实现在 2×A800 上
用 PRM-Lite + LATA 才把它救回来。本项目问三个问题：

1. **同样的问题在 1/10 算力、1/5 参数量的配置下是什么形态？**
2. 参考实现诊断出的病因，哪条在小模型上**放大**、哪条**消失**、有没有**新的**？
3. ⭐ 参考实现摆了 14 个工具却**从没分析过工具调用的分布** ——
   工具使用行为本身会不会也是一种可观测的退化？

---

## 2. 主要发现

### 2.1 ⭐ 不是坍塌，是"没信号"

GRPO 的组内归一化 `A_i = (r_i − mean) / (std + eps)`：**一组 8 条轨迹奖励全同时，
advantage 精确为 0，这一步不产生任何梯度**。

单臂 25 轮实测：

| | 起点（SFT 后） | 稳态（后 8 轮） |
|---|---|---|
| **组内零方差率** | 0.742 | **0.964**（峰值 1.000 出现两次） |
| 通过率 | 0.129 | ~0.16，**全程无趋势**（逐轮区间 0.125–0.173） |

25 轮 × 31 组 = **775 个组，累计只有 59 个产生过梯度**。
而且零方差率**被训练推高了**（0.742 → 0.964），方向和"训练中涌现的困难"相反。

**四臂消融**（LATA × dynamic sampling 的 2×2）把这条钉死了 ——
四种配置的零方差率全是平线：

| 臂 | 长度归一化 | 采样策略 | 零方差率 | 通过率 | 工具调用（末轮） |
|---|---|---|---:|---:|---:|
| `arm_vanilla` | ÷L | — | 88.3% | 12.5% | 3.59（**0.51×**） |
| `arm_ds` | ÷L | dynamic sampling | 89.5% | 19.4% | **7.07（1.00×）** |
| `vanilla` | ÷√L (LATA) | — | 93.1% | 16.2% | 5.04（0.71×） |
| `arm_lata_ds` | ÷√L (LATA) | dynamic sampling | 87.2% | 16.6% | 3.98（0.56×） |

> 工具调用的参考线：**gold 成功轨迹均值 7.10**（中位 6）。

**结论：算法轴上的改动改变不了零方差率** —— 病根在**数据侧的难度校准**。
（数据侧审计见 §2.4：参考数据集 50 道题里只有 31 道有区分度。）

### 2.2 ⭐ 工具使用退化谱：过调用 → 欠调用

单臂 25 轮，工具调用数的轨迹：

```
gold 成功轨迹            7.10  ─────────────────────
SFT 后第 0 轮           15.73  = 2.22×  过调用
稳态（末轮）             3.47  = 0.49×  欠调用
```

**不是"过调用慢慢收敛回正常"，是一路穿过正常区掉到另一个极端。**

这不是"话变少了"：**轮数全程在 14.9–19.2 之间、没有趋势**，而工具调用掉到 3.47 ——
稳态下平均 18.6 轮里只有 3.9 次工具调用，**约 15 个 turn 不发生任何工具调用**。
逐题解剖显示这些 turn **近乎空的（≤5 字符）为 0**、文本中位长度上千字符
⇒ **是"少做事、多说话"，不是空转**。

四臂对照给出了更有分辨力的版本 —— **关键不是"掉不掉"，是"掉到哪"**：
四条臂全部从 ~16 掉下来，但只有 `arm_ds` **停在 gold 线上（1.00×）**，
其余三条掉穿到 0.51–0.71×（单 seed，当线索看）。

### 2.3 LATA 的纯效应（干净对照）

`arm_ds` vs `arm_lata_ds`：**同样的 31 道题、同一个起点 adapter、同为 dynamic sampling，
唯一差别是长度归一化 ÷L vs ÷√L**。

| | `arm_ds` (÷L) | `arm_lata_ds` (÷√L) | 比 |
|---|---:|---:|---:|
| token / 条（末轮） | 2,797 | **6,068** | **2.2×** |
| 工具调用（末轮） | 7.07 | 3.98 | 0.56× |
| `ds_passes`（末轮，12 轮对齐） | 2 | **5**（上限 6） | — |

⇒ **÷√L 不惩罚长轨迹 ⇒ 输出变长 2.2 倍 ⇒ 更早撞上下文上限、工具调用被文本挤掉。**
这正是 LATA 设计出来要造成的方向，被独立复现了。

### 2.4 数据侧审计：50 道题里只有 31 道有区分度

对 τ-bench airline 的 50 道题做四路探针（`noop` 什么都不做 / `gold` 重放 /
`readonly` 只读 / `foreign` 注入别题写动作）：

| 类别 | 判据 | 题数 |
|---|---|---:|
| **S · 有区分度** | 不做 = 0 分，做对 = 1 分 | **31** |
| **O · 单边信号** | 不做 = 满分，**乱做 = 0 分** | **19** |
| **N · 真无信号** | 不做满分 且 乱做也满分 | **0** |

⚠️ **这 19 道题不是"无信号"，是"只有惩罚方向"**：它们本来就不需要任何写动作，
不存在"做对了"这个状态。放进 GRPO 后，惩罚信号来得比奖励信号**更早也更密**
—— 这是"欠调用"的一个数据侧解释。

**参考实现没有报告这条**：它写"50 题是核心约束"，实际有区分度的只有 31 道。

### 2.5 工程账（单卡可行性）

| | 实测 |
|---|---|
| 训练峰值显存 | **5.15 GB**（8192 token，LoRA r=16，开梯度检查点） |
| 训练速度 | 2.1 秒 / 步 |
| 权重加载 | 5.2 秒 / 2.88 GB |
| vLLM 启动（每轮一次） | 119.8 秒 |
| 每轮规模 | 31 题 × 8 条 = 248 条轨迹 ≈ 22 分钟 |

**关键约束是显存不是算力**：只用了 24GB 的 21%。
一个反例：漏开梯度检查点时，单条 8192 token 轨迹要吃 **22.5 GB** → OOM。

## 3. 怎么复现

### 3.1 环境

```bash
# Python ≥ 3.10（τ-bench 用了 match 语法，3.9 连 import 都过不去）
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### 3.2 τ-bench（第三方依赖，本项目**不打包**）

按以下任一方式提供τ-bench，`env/bootstrap.py` 会依次尝试：

2. 项目同级的 `../tau-bench`

4. 原开发机布局

```bash
git clone <tau-bench 仓库> ../tau-bench
export TAU_BENCH_PATH=$(pwd)/../tau-bench
```

### 3.3 Stage 0：数据侧审计（**纯 CPU，零模型，零 GPU**）

这是复现的起点 —— 不需要任何模型就能跑出 §2.4 的结论：

```bash
python scripts/verify_oracle.py           # gold 重放 oracle，期望 50/50
python scripts/probe_signal_shape.py      # 四路探针 → S/O/N 分类
python scripts/token_stats.py             # 轨迹 token 分布（需 Qwen tokenizer）
python scripts/analyze_hackable.py        # 无区分度归因
python scripts/build_task_split.py        # 生成 31 + 19 的分流清单
python scripts/expand_tasks.py            # 扩题器 → 800 道分级任务
```

### 3.4 训练（需要 GPU）

```bash
# SFT 预热
python -m train.trainer sft --model <Qwen2.5-1.5B-Instruct> \
  --sft-data data/sft_final.jsonl --out models/adapter_sft

# GRPO
python -m train.run --rounds 10 --select train --n 8 \
  --model <Qwen2.5-1.5B-Instruct> --init-adapter models/adapter_sft \
  --max-seq-tokens 16384 --length-norm mean --run-name demo
```

`--select` 可选：`train`（31 道 S 类）/ `probe`（19 道 O 类）/
`exp_easy` / `exp_medium`（扩题集的简单/困难档）。

### 3.5 分析（**纯 CPU**）

```bash
python scripts/analyze_arms.py                                   # 四臂对照表 + 图
python scripts/analyze_rollouts.py runs/<臂>/rollouts/step_009.jsonl --s-max 16384
python scripts/make_figs_h7.py                                   # 起点 vs 末值主图
```

## 4. 方法

### 4.1 分时复用单卡

vLLM 和训练**不能同时驻留**（峰值会撞在一起）。本项目让两者用文件交接、分时复用：

```
起 vLLM → 采 248 条轨迹 → 落盘 jsonl → kill vLLM → 训练 → 存 LoRA adapter（37MB）→ 下一轮
```

⭐ 副产品：**每条轨迹的原始对话全部落盘**，观测指标可以离线重算，
补一个指标不需要重新租卡。

### 4.2 关于 dynamic sampling 的一个实现细节

参考实现（DAPO）用"**过滤**零方差组"来避免空更新。本项目**没有照字面实现**：

本项目的 GRPO 是**每条轨迹一次 `optimizer.step()`**、分母是**该轨迹自己的长度** ⇒
零 advantage 的轨迹贡献 0 梯度、**也不稀释别人的梯度** ⇒
**"过滤"在这个实现下是恒等变换，是个空臂**。

所以它被实现成**加采**：一遍遍重采样直到攒够 K 个有方差的组，
报告的是**有效更新步数**。基线臂稳态每轮 248 次 `optimizer.step()` 里约 240 次是空转。

### 4.3 观测指标

| 指标 | 为什么 |
|---|---|
| **组内零方差率** | 第一监控指标。全对和全错都不给梯度，**只有组内有对有错才有信号** |
| **工具调用数** | 主创新点的落点，对照 gold 成功轨迹的 7.10 |
| **有效更新数** | `(1 − 零方差率) × 组数 × 每组条数` —— 这一轮真正产生梯度的轨迹数 |
| 截断率 / 格式崩率 | 被截断的轨迹**强制判 0**，不给部分奖励（否则等于奖励"啰嗦到被截断"） |

## 7. 已知限制

诚实列出，避免过度解读：

1. **单 seed、单次运行**。四臂各只跑了一次，曲线上的小波动不能当趋势读。
2. **规模**：1.5B + LoRA。结论**不能直接外推到 7B/全参**。
3. **DS 臂的 rollout 落盘是过滤后的子集**（只存被选进训练的组），
   所以跨臂的逐题对比只能取两条非 DS 臂。
4. **"欠调用"与"零方差率上升"只是相关**，混淆变量未排除。
5. **`arm_vanilla` 与 `arm_ds` 的起点零方差率不齐**（0.806 vs 0.871，抽样噪声量级）。
6. **四臂按最少轮对齐（12 轮）**：其中一条臂因训练容器重启中断，未跑满 15 轮。

## 8. 与参考实现的关系

本项目**不是** `agentic-grpo-longhorizon` 的复刻，也不声称达到它的工程深度。
明确区分：

| | 参考实现 | 本项目 |
|---|---|---|
| 硬件 | 2×A800 | **1× RTX 4090D 24GB** |
| 模型 | 7B + LoRA + 72B 用户模拟器 | **1.5B + LoRA + 规则用户模拟器** |
| 工具 | 14 | **12** |
| 上下文 | 8192 + 12288 | 16384（单段） |

**本项目的增量**：① 工具使用行为退化谱（它没做）② 零方差率的**来源分解**
（结构性 vs 涌现性）③ 单卡可行性账 + 4 个"只有真卡才暴露"的工程坑。

参考实现中**没有采用**的：ContextVar 并发隔离 / bypass_mode / Render-Twice-Diff /
异步 pipeline / veRL 全栈。

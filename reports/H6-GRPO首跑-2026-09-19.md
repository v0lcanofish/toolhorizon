# 三、⭐ 三条主要结果

## ① 零方差率**上升**：0.742 → 0.952（峰值 1.000）

| | 零方差率 |
|---|---|
| SFT 起点 | 74.2% |
| 前 3 轮 | 76.3% |
| **后 8 轮（稳态）** | **95.2%** |
| 峰值 | **100.0%**（step 12） |

**稳态下只有约 5% 的组有梯度。** 25 轮 × 31 组 = 775 组，**累计只有约 40 组产生了梯度**。

⇒ **这就是项目立项时写的最大风险：「不是坍塌，是没信号」的实测形态。**

⇒ 也说明「零方差 = 训练中涌现的」这个说法在我们的场景里**方向是反的** ——
它不是在训练中被治好的，是**被训练推高的**。

## ② ⭐⭐ 工具调用：从「过调用」翻成「欠调用」

```
gold 真实成功轨迹        7.1（中位 6）
SFT 之后（GRPO 之前）    14.94  = gold 的 2.10 倍   → 过调用
前 3 轮                  11.82  = gold 的 1.67 倍
后 8 轮（稳态）           3.95  = gold 的 0.56 倍   → **欠调用**
```

**这是「工具使用退化谱」这个创新点的第一份真实训练证据** ——
而且形态比预期更狠：**不是"过调用慢慢收敛回正常"，是一路穿过正常区、掉到另一个极端。**

⚠️ **但它和 ① 是同步发生的**（step 3→7 那一段，工具调用 10.05→4.32，零方差 0.807→0.968）。
**相关不等于因果**，而且有一个明确的混淆变量（见 ④）。

## ③ 通过率**没有提升**

0.129 → 稳态 ~0.153，**全程在 0.125–0.173 之间波动，没有趋势**。
`reward_mean` 与 `pass_rate` **每一轮完全相同** —— 说明奖励是纯 0/1，没有部分学分。

> 参考实现（longhorizon）报的是 Base 0.160 → SFT 0.145（反降）→ GRPO 峰值 0.225 → 坍塌 0.175。
> **我们这边连"峰值"都没出现** —— 因为起点就没信号（见 ①）。

## ④ 变慢 4 倍的真因：**token 多了，不是机器慢了**

```
new_tokens   443k → 1812k   （×4.1）
tok/sec       830 →   1119   （×1.35）  ← 基本没变 = 硬件没问题
秒/条        2.15 →   6.53
```

⚠️ **而且"工具调用降了 4 倍"和"token 涨了 4.1 倍"是同时发生的** ——
`turns_mean` 全程稳定在 **~18.5**，而 `tool_calls_mean` 掉到 **~4.0**：

```
⇒ 约 14 个 turn 里没有任何工具调用。
⇒ 模型没有"少说话多做事"，而是"少做事、多说话" —— 输出变冗长了。
```

**这是下一步最该查的一件事**（见 §五）。

# 四、⚠️ 一条必须先说的保留意见（别过度解读）

**「欠调用」这个判断有取样偏差，我自己先指出来：**

```
gold 的 7.1 是**成功轨迹**上的统计量。
而我们稳态的 pass_rate 只有 15% —— 也就是说，我们统计的轨迹**大多数是不成功的**。
```

**拿"失败轨迹的工具调用数"去和"成功轨迹的 gold"比，本身是有偏的。**
诚实的说法是：**我们不知道那 3.95 里有多少是"学会了少调工具"，有多少是"放弃了尝试"。**

⭐ **正确的对照应该是**：在同一批题上，**成功轨迹 vs 失败轨迹**各自的 tool_calls
（同一个策略、同一个分布下比）。`scripts/analyze_rollouts.py` 已经能做这件事，
但它需要 rollout 原始文件（在 AutoDL 上，每份 10MB）。

# 五、跑完（ETA 02:02）要先做的三件事

1. **零方差拆成全对 / 全错**（`analyze_rollouts.py`）——
   现在只知道"95% 的组没梯度"，不知道是"全对"还是"全错"。
   pass_rate 15% ⇒ 大概率主要是全错，但**必须量出来才能写进报告**。
2. **工具调用按结局拆**（成功 vs 失败轨迹）—— 修掉 §四 的取样偏差。
3. **那 14 个不调工具的 turn 到底在干什么** —— 是推理文本、还是重复空转？
   这决定了 ② 该叫「欠调用」还是「空转」。

# 六、诚实边界

1. **本报告是 22/25 轮的快照**，最后 3 轮可能改变末端数值（但稳态已很稳：后 8 轮零方差 0.935–0.968）。
2. **「欠调用」有取样偏差**（见 §四）。
3. **零方差率与工具调用的同步只是相关**，混淆变量未排除。
4. **只有单次运行、单一 seed** —— 没有方差估计，曲线上的小波动不能当趋势读。
5. **这是 1.5B 的结论**，不能外推到 7B（参考实现做的是 7B）。

# 奖励信号形状探针 · 实测报告

> 2026-09-16 ｜ 脚本：`scripts/probe_signal_shape.py`（零模型 / 零 GPU / 可复现）
> 数据：`data/signal_shape.json`
> **本报告推翻了 9/15 报告的一处判断。**

---

# 一、结论

| 类别 | 判定条件 | 题数 | 占比 |
|---|---|---:|---:|
| **S 有区分度**（正常训练题） | `noop=0` 且 `gold=1` | **31** | 62.0% |
| **O 单边信号**（只惩罚过调用） | `noop=1` 且 `foreign=0` | **19** | 38.0% |
| **N 真·无信号**（怎么都能过） | `noop=1` 且 `foreign=1` | **0** | **0.0%** |

> ⭐ **没有一道题是"真·无信号"。19 道全部是【单边信号】。**

---

# 二、⭐ 推翻 9/15 的一处判断

## 9/15 报告写的是

> "20 道（40%）的题 gold 改不动数据库 → **reward 与策略行为无关、恒为 1.0**"

## 实测结果是

**这两句都不准确。**

1. **是 19 道不是 20 道**（9/15 自己也算出 noop 通过 19 道，两处口径没对齐）
2. ⭐ **"reward 与策略行为无关"是错的** —— 注入别的题的 gold 写动作后，这 19 道**全部掉到 0.0**

```
task[12]  noop=1.0   注入 foreign 写动作=0.0
task[13]  noop=1.0   注入 foreign 写动作=0.0
...（19 道全部如此）
```

## 正确表述

> **这 19 道题的 reward【与策略行为有关，但是单向的】——**
> **只惩罚"乱做"，不奖励任何"正确行为"。**
>
> 因为这道题**本来就不需要动作**，所以不存在"做对了"这个状态，
> 只存在"做错了"（动了 DB 且改错）。

---

# 三、这个区别为什么重要

## 3.1 它在 GRPO 里的行为完全不同

| | 真·无信号（N） | **单边信号（O）** |
|---|---|---|
| 组内 8 条全不动 | std=0，A=0 | std=0，A=0 |
| 组内**有 1 条乱动** | 仍是 1.0，std=0 | **拿 0，std>0 → 有梯度** |
| 梯度方向 | 无 | ⭐ **"别调工具"** |

**N 类是纯粹的浪费；O 类是有毒的——只要有 rollout 乱动，就产生"别动"的梯度。**

## 3.2 ⭐ 两类题在训练里是**互相打架**的

```
S 类（31 道，62%）：做了对的事 → +1 ；不做 → 0      →  教"该动就动"
O 类（19 道，38%）：不做 → +1 ；乱做 → 0            →  教"别乱动"
```

**对一个弱策略，这两股梯度是不对称的**：

- S 类要它学会**具体的、正确的动作序列**（难，稀疏）
- O 类只告诉它**"动作有风险"**（易，密集）

**结果：惩罚信号比奖励信号更容易被学到 → 模型变保守 → 欠调用。**

> ⭐ **这才是"欠调用"的真正机制**——不是"没信号所以不学"，而是
> **"有信号，但只有惩罚方向的信号，且惩罚来得比奖励早、比奖励密"。**

## 3.3 与 Tool-Overuse Illusion（arXiv 2604.19749）的关系

那篇的结论是"**outcome-only reward 导致过调用随训练恶化（+65%）**"。

**两者不矛盾，是配比问题**：
- 31 道题（62%）在**奖励**动作 → 推动过调用
- 19 道题（38%）在**惩罚**动作 → 推动欠调用
- **净效果取决于两边的梯度强度对比** —— 这是一个**可测量的量**

**这是新的实验设计点**：不是"会不会退化"，而是"**往哪个方向退化取决于 S/O 配比**"。

# 四、一个意外的细分发现

`task[44]` 是 **S 类但 `n_write=0`**：

```
S  44   写动作 0   outputs 1   noop=0.0  gold=1.0  只读=0.0  foreign=0.0
```

**它的正解是：不改 DB，但必须把信息汇报给用户。**
（`outputs=["4"]`，noop 因为没 respond 所以拿 0）

**这是第四种信号形状**——「**纯沟通型任务**」：

| 类型 | 正解 | 数量 |
|---|---|---|
| S-写 | 改 DB | 30 |
| **S-纯沟通** | **不改 DB，但汇报** | **1**（task[44]） |
| O | 不做（无人可沟通） | 19 |

⚠️ 只有 1 道纯沟通题——**占 2%**。这说明 τ-bench airline 里"只沟通不动手"的能力几乎没被覆盖，
而扩题器如果不生成 `outputs`，这个能力会被彻底稀释掉（见设计补全文档洞 3）。

# 五、复现方式

```bash
cd 代码库/projects/ToolHorizon
PYTHONIOENCODING=utf-8 python3.13 scripts/probe_signal_shape.py
```

四路探针：
| 探针 | 动作 | 模拟什么 |
|---|---|---|
| `noop` | 什么都不做 | 最保守策略 |
| `gold` | gold 重放（+合成 respond） | 完美策略 |
| `readonly` | 只做 gold 里的只读动作 | 欠调用 |
| `foreign` | 注入别题的 gold 写动作 | **过调用** |

## ⭐ 新实验 D｜S/O 配比 → 退化方向

```
三个训练臂，只改 S : O 的配比：
  Arm 1：31 S + 19 O   （原始，38% 惩罚）
  Arm 2：31 S +  0 O   （无惩罚压力）
  Arm 3：31 S + 38 O   （人为放大惩罚压力，O 类过采样 2×）

观测：工具调用数随训练步数的漂移
预期：Arm 3 的欠调用最严重，Arm 2 最轻
     → 建立「惩罚型样本占比」与「退化方向」的定量关系
```

**这是本项目最核心的一个新实验**——它把"欠调用"从"模型学坏了"变成了
**"数据配比导致的、可预测的、可控的"现象**。
